# 02 VibeCoding 能力矩阵

## 旧实现情况

当前功能按通用 Agent 逐年叠加。手机控制、Android 调试、浏览器自动化、截图、Shizuku 等底层能力存在用途重叠，不能凭名称整块删除。

## 意图修正

以“是否直接支撑编码任务闭环”为唯一标准，对所有用户入口和底层能力做可审计分类。

## 预期新实现

建立矩阵覆盖：

- 全部内置工具
- ToolPkg/MCP/Skill 能力
- 所有导航路由和设置页
- Manifest Activity/Service/Receiver/Provider 与权限
- Gradle 模块和生产依赖
- assets、native 库、项目模板和多语言资源
- Provider 和功能模型类型

每项必须标记：`保留`、`拆分后保留`、`删除`，并附入口、反向依赖、VibeCoding 场景和验证方法。

## 作用域

只读源码分析和文档。不得在矩阵确认前删除业务文件。

## 验证

矩阵计数与自动扫描一致；所有删除项都有反向依赖结果；所有保留项都有至少一个具体编码场景；用户完成产品取舍确认。

## 风险

- 将 Android 开发调试误判为手机控制
- 将底层共享依赖随上层产品功能一起删除
- 漏掉动态注册工具或 Manifest 入口

## 回滚

矩阵是文档资产。发现遗漏时更新矩阵并重新走用户确认，不因先前分类自动触发代码删改。
