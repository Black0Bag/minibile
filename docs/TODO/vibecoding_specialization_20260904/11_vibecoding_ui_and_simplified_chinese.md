# 11 VibeCoding 工作台与简体中文收敛

## 旧实现情况

当前 UI 面向通用 Agent，主侧边栏、工具箱、设置和聊天输入区承载大量与编码无关入口。默认中文资源较完整，但核心运行过程仍暴露英文工具协议 ID。两套聊天输入样式增加状态 UI 的重复实现风险，公共 Composable Preview 很少。

## 意图修正

围绕编码任务闭环重组信息架构：项目、Plan/Build、TODO、Subagent、终端、模型与结果验证在同一工作台中清晰可达；最终用户无需理解内部协议或通用手机助手概念。

## 预期新实现

### 主工作台

- 当前项目和工作区是第一视觉信号
- 输入区提供清晰但紧凑的 Plan/Build 分段切换控件
- 用户切换模式时展示权限变化摘要，不由 Agent 触发
- TODO Dock 位于输入区附近，可折叠
- 当前 Subagent、后台任务、暂停/恢复状态有独立可见区域
- 工具动作显示简体中文名称、对象、进度和结果
- 终端、文件差异、测试结果和预览可以快速进出，不遮挡对话

### 导航

最终导航只保留经能力矩阵批准的 VibeCoding 入口，例如：

- 编码对话/任务
- 项目与工作区
- 终端
- 记忆
- 扩展管理：MCP、Skill、ToolPkg
- 模型配置
- 编码 Agent 设置与诊断

实际入口名称和布局需在删除完成后的真实功能集合上设计，本文不提前固定页面数量。

### 简体中文

- 模式、TODO、Subagent、工具活动、模型能力、暂停恢复、权限和错误全部使用自然简体中文
- 技术协议 ID 仅在调试详情显示
- 删除非编码领域后清理对应文案
- 最终产品体验不要求其他界面语言
- 是否物理删除 `values-en` 等目录需先确认资源、构建和插件依赖；不能为了中文化破坏协议或代码生成

### Compose 与无障碍

- 状态由单一 ViewModel/Repository 驱动，不在多个 Composable 复制状态机
- 交互目标至少 48dp
- 图标按钮有准确的动作型 `contentDescription`
- 模式、TODO 和 Subagent 自定义控件暴露 selected/checked/progress/stateDescription 语义
- 标题提供 heading 语义，焦点顺序符合视觉顺序
- 普通文本对比度至少 4.5:1，图标和大文本至少 3:1
- 长工具名、路径和错误信息在手机/平板均不重叠
- 新关键组件提供浅色、深色和主要状态 Preview

## 作用域候选

- `ui/main/` 与 `ScreenRouteRegistry.kt`
- `ui/features/chat/`
- `ui/features/settings/`
- `ui/features/toolbox/`
- `ui/features/packages/`
- 主题、图标与 strings
- 新 TODO/Subagent/模式/恢复 UI
- 手机与平板布局

## 验证

- 首次启动到完成编码任务的可用性走查
- Plan/Build 仅用户可切换，状态清晰
- TODO 和后台任务不遮挡输入与消息
- 所有核心运行状态无裸英文协议 ID
- 手机和至少一种平板宽度截图对比
- 浅色/深色模式
- TalkBack、键盘焦点、48dp 触控和颜色对比检查
- 最长路径、中文错误、多工具并行和多个 Subagent 压力布局
- 已删除功能无导航、设置、搜索结果或帮助残留

## 风险

- 先设计最终导航、后删除功能会反复返工
- 两套输入样式各自实现 TODO/模式导致状态漂移
- 过度中文化破坏协议名或开发者诊断能力
- 状态元素过多挤压移动端输入区
- 动画影响长任务性能和无障碍体验

## 回滚

先建立共享无状态组件和 Preview，再接入主聊天。旧入口在新入口通过验收后才删除。每个 UI 区域独立提交；视觉问题可回退组件提交，不回退数据和权限内核。
