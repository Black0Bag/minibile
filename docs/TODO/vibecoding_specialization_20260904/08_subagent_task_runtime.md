# 08 Subagent 任务运行时

## 旧实现情况

当前应用支持多会话和并行运行，也有角色卡与手机 UI 子代理，但没有面向编码任务的父子会话、任务委派、专业 Agent 配置、后台完成通知或继续既有子任务机制。

OpenCode 官方源码已确认其任务机制包含：父会话创建子会话、前台或后台运行、`task_id` 继续既有子会话、后台完成后主动注入结果、深度限制和独立权限规则。本项目要求更严格：父会话 Plan deny 必须是所有后代的硬上限。

## 意图修正

建立面向 VibeCoding 的专业任务委派系统。Subagent 负责独立、可界定、可验证的工作单元，不替代主代理决策，也不能扩大用户选择的会话模式。

## 预期新实现

### Agent 配置

每个 Agent 定义：

- 稳定 ID、简体中文名称和使用说明
- `PRIMARY` 或 `SUBAGENT` 类型
- 可选模型与参数
- 专属系统 Prompt
- 工具能力规则
- 最大步骤数
- 是否允许后台运行
- 是否允许再委派
- 可声明的文件或模块作用域

具体内置 Subagent 类型在实现前依据能力矩阵确定，不直接照搬其他项目名称。

### 任务数据

`SubagentTask` 至少包含：

- 任务 ID
- 父会话 ID 与子会话 ID
- 父 TODO ID
- Subagent 类型
- 用户/主代理给出的任务描述
- 前台或后台模式
- 声明的文件和模块作用域
- 状态、创建时间、开始时间和结束时间
- 结果摘要、证据、变更范围、失败原因和未完成项

### 生命周期

- 主代理通过唯一 `task` 能力创建任务
- 创建前由硬门禁校验模式、Agent 类型和作用域
- 前台任务完成后返回结构化结果
- 后台任务立即返回任务 ID；完成、失败或取消时主动发事件给父会话
- 主代理不得 sleep 或轮询后台任务
- 传入既有任务 ID 时继续同一子会话
- 默认最大深度为 1，Subagent 不能继续委派
- 用户可查看、取消和进入子会话

### 权限

- Plan 只允许只读 Subagent
- 父会话所有 deny 规则作为后代硬上限
- 子代理自身规则只能进一步收紧
- Build 子代理按最小任务作用域获得权限
- 子代理默认不能修改父会话 TODO
- 并行写任务必须声明作用域；重叠文件或目录不能同时执行
- 动态 Agent、ToolPkg 或配置文件不得覆盖会话硬上限

### UI

- 父消息中显示子任务卡片：名称、状态、耗时、当前摘要和作用域
- 后台任务完成时非打断式通知
- 可进入子会话查看完整工具轨迹
- 明确区分排队、运行、暂停、完成、失败和取消
- 与父 TODO 项建立可见关联

## 作用域候选

- Chat/Message 数据模型与 Room
- `ChatRuntimeSlot.kt`、`ChatRuntimeHolder.kt`
- `ChatHistoryManager.kt`
- 新 AgentCatalog、SubagentTaskRepository 和 TaskCoordinator
- `EnhancedAIService.kt` 的模型请求入口
- 工具注册和 `ToolExecutionContext`
- ChatViewModel、消息渲染和会话导航
- 后台前台 Service 生命周期

## 验证

- 父子会话关系和任务状态单测
- Plan 子代理尝试写文件、Shell 写入、调用写包工具均被拒绝
- 自定义 Subagent 不能提高父会话权限
- Build 子代理只能在声明作用域写入
- 两个不重叠任务可并行，重叠任务被排队或拒绝
- 后台完成主动通知，不需要轮询
- 继续既有任务保留同一子会话和上下文
- 深度限制、取消和父会话终止行为明确
- 失败结果包含证据和未完成项

## 风险

- 并行任务修改冲突
- 子会话数量和上下文导致 Token、内存与数据库膨胀
- 父会话取消时后台任务继续产生副作用
- 权限合并顺序错误导致越权
- 结果注入父会话时触发不必要的新模型轮次

## 回滚

Agent 配置、任务数据、运行协调和 UI 分阶段提交。后台模式最后启用；前台单子任务先通过权限和生命周期测试。任一权限测试失败即停止，不发布 Subagent 功能。数据无需向旧版兼容，回滚后清除应用数据。
